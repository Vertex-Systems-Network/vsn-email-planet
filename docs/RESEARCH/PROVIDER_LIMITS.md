# Provider limits and validation status

- **Gmail:** stale/invalid history IDs can return HTTP 404; documented recovery is a full sync. Watch lifecycle, scopes and policy requirements remain to be researched before adapter implementation. Source: `STANDARDS.md`.
- **Microsoft Graph:** message delta is folder-oriented and returns continuation/delta links; supported query options are limited. Permissions and lifecycle/webhook requirements remain open before adapter implementation.
- **cPanel/WHM:** Developer portal states the function documentation applies to cPanel & WHM v138 and older versions may lack functions. The Email Accounts UI docs cover v130 through latest and say providers can disable the interface via WHM Feature Manager. API tokens can run API functions on cPanel account data/settings. Sources: [Developer portal](https://api.docs.cpanel.net/), [Email Accounts](https://docs.cpanel.net/cpanel/email/email-accounts/), [API tokens](https://api.docs.cpanel.net/cpanel/tokens), [UAPI introduction](https://api.docs.cpanel.net/cpanel/introduction). Live host version, token restrictions and mail-feature state need per-connection probing.
- **Plesk:** XML API documents role-scoped access; customers can inspect/manage mail accounts for their own sites. XML API version and reseller permissions must be discovered. Sources: [Managing Mail](https://docs.plesk.com/en-US/obsidian/api-rpc/about-xml-api/reference/managing-mail.34477/), [Getting Mail Account Settings](https://docs.plesk.com/en-US/obsidian/api-rpc/about-xml-api/reference/managing-mail/getting-mail-account-settings.34514/).
- **DirectAdmin:** vendor documents a new API and legacy API; exact email actions, supported versions and scope remain to be mapped before choosing an adapter. Source: [API access](https://docs.directadmin.com/developer/api/index.html).
- **Generic IMAP/SMTP:** RFC/protocol, TLS, auth and server-specific behavior research remains open.

No actual provider connection or limit was tested against a live account. cPanel UAPI docs were reviewed; legacy API2 endpoints remain visible in official docs, so implementation should use current supported UAPI operations unless a verified compatibility case is documented.
